Tokens & Cost

Every word costs money. Here's how to budget for it.

Try This Right Now

Type "I love product management" into a tokenizer.

Result: ["I", " love", " product", " management"] — 4 tokens.

Now imagine your chatbot handles 10,000 queries/day. Each query averages 500 tokens in + 300 tokens out. That's 8 million tokens/day.

At GPT-4o pricing, that's ~$60/day or $1,800/month just for the API.

What Is a Token?

A token is roughly 4 characters or 0.75 words. It's the unit LLMs "think" in — and the unit you pay for.

Simple Words

"hello" = 1 token

"Hello," = 2 tokens

Punctuation and capitalization affect token count

Common Phrases

"artificial intelligence" = 2 tokens

"I love product management" = 4 tokens

Common words are single tokens

Technical Terms

"tokenization" = 3 tokens

"pneumonoultramicro..." = 9 tokens

Rare/long words get split into more tokens

PM Decision Point

You pay for both input AND output tokens. The cost equation is:

Total Cost = (Input Tokens × Input Price) + (Output Tokens × Output Price)

Output tokens typically cost 2-4x more than input tokens. This means controlling output length saves more money than shortening prompts.

Context Windows: How Much Can the Model "See"?

The context window is the total input + output the model can handle in one request. Think of it as the model's working memory.

Model Context Window Real-World Meaning Use Case
GPT-4o 128K tokens ~96K words / ~300 pages Long documents, code analysis
Claude 3.5 Sonnet 200K tokens ~150K words / ~500 pages Entire codebases, book analysis
Gemini 1.5 Pro 1M tokens ~750K words / entire codebase Video transcripts, massive docs
GPT-4o-mini 128K tokens ~96K words Budget-friendly long context
The "Lost in the Middle" Problem

Just because a model has a 200K token context window doesn't mean it uses all of it well. Research shows LLMs tend to pay most attention to the beginning and end of the context, often missing information in the middle.

PM Lesson: Bigger context window ≠ better results. A 4K-token prompt with the right information beats a 100K-token dump of everything.

PM Cost Framework

For any LLM feature, calculate:

  1. Average tokens per query (input + output)
  2. Expected queries per day
  3. Monthly cost = tokens × queries × 30 × price per token
  4. Scale factor — what happens at 10x or 100x usage?

A feature that costs $50/month at launch can cost $50,000/month at scale.

5 Ways to Reduce Token Costs

1. Use a Smaller Model

GPT-4o-mini is 17x cheaper than GPT-4o. For many tasks, quality is comparable.

2. Limit Output Length

Set max_tokens to cap response length. Output tokens cost 2-4x more than input.

3. Cache Common Queries

If 20% of queries are the same, cache those responses. Zero token cost for repeats.

4. Shorten System Prompts

Your system prompt is sent with every query. A 500-token system prompt × 10K queries/day = 5M extra tokens/day.

5. Route by Complexity

Use a cheap model for simple queries, expensive model for complex ones. This alone can cut costs 60-80%.

Quick Check

Your chatbot handles 5,000 queries/day. Average: 400 input tokens, 200 output tokens. You're using GPT-4o ($2.50/1M input, $10/1M output). What's the approximate monthly API cost?

Stakeholder Framing

When your CTO says "Let's just use GPT-4o for everything":

"GPT-4o costs 17x more per token than GPT-4o-mini. At our projected volume of 50K queries/day, that's the difference between $300/month and $5,100/month. Let's route simple queries to the cheaper model and reserve GPT-4o for complex ones."
