SECTION 6.1

Evaluation Frameworks

Different AI Types Need Different Metrics

The Core Problem

Traditional software testing is binary: it works or it doesn't. AI evaluation is probabilistic: it works most of the time, kind of well, for certain inputs. This requires entirely different evaluation frameworks.

Evaluation by AI Type

AI Type Primary Metrics Evaluation Method Key Challenge
Classical ML Accuracy, Precision, Recall, F1, AUC Hold-out test set, cross-validation Data drift over time
LLM Features Relevance, Accuracy, Helpfulness, Safety Human evaluation, LLM-as-judge Subjective quality, no ground truth
RAG Systems Retrieval precision, Answer faithfulness, Groundedness RAGAS framework, human review Hallucination despite good retrieval
Agents Task completion rate, Steps to completion, Error rate End-to-end testing, trajectory analysis Multi-step failures, cascading errors

PM Decision Point

You need evaluation at EVERY level. Many teams skip to A/B testing without the foundation - that's how Galactica happened.

  • Unit tests: Engineering owns, but PM defines requirements
  • Integration tests: PM defines realistic scenarios
  • Human evaluation: PM designs rubric and selects evaluators
  • A/B testing: PM defines success metrics and sample sizes

LLM Evaluation Dimensions

Factual Accuracy

Is the information correct? Can it be verified?

Measure: Fact-checking against sources

Relevance

Does the response answer the actual question?

Measure: Semantic similarity to ideal response

Helpfulness

Does it actually help the user accomplish their goal?

Measure: Task completion rate

Harmlessness

Does it avoid harmful, biased, or inappropriate content?

Measure: Safety classifier scores

Coherence

Is the response well-structured and easy to understand?

Measure: Readability scores, human ratings

Format Compliance

Does it follow the requested format (JSON, bullets, etc.)?

Measure: Parsing success rate

Common Evaluation Mistakes

Anti-Patterns to Avoid
  • Single metric obsession: Optimizing only for accuracy while ignoring safety
  • Test set contamination: Training data that overlaps with evaluation data
  • Benchmark gaming: Optimizing for benchmarks that don't reflect real usage
  • Skipping human eval: Trusting automated metrics blindly
  • Static evaluation: Not re-evaluating as the model or data changes

How to Explain Evaluation Frameworks to Stakeholders

"We evaluate AI like we'd evaluate a new employee. We check if they know the facts, if they understand the question, if they're actually helpful, and if they're professional. We do this with a mix of spot-checks (human review) and automated monitoring (AI judges). And we keep checking - because unlike employees, AI can drift over time."
