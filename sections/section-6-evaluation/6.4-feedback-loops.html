Feedback Loops

Continuous Improvement Through Monitoring

Evaluation Never Stops

Launch isn't the finish line - it's the starting line. AI systems drift, user needs change, edge cases emerge. You need continuous evaluation to catch problems before users do.

Key Metrics to Monitor

Metric What It Tells You Alert Threshold
User engagement rate Are users finding value? >20% drop from baseline
Thumbs down rate Direct dissatisfaction signal >5% of responses
Edit/regenerate rate Output not meeting needs >15% of responses
Task completion rate Actually solving problems? >10% drop from baseline
Latency P95 Performance degradation >2x baseline
Safety classifier triggers Harmful content attempts Any unexpected spike
PM Decision Point

Set up dashboards BEFORE launch that answer:

  • Is the AI still performing as well as during testing?
  • Are there new failure patterns we didn't see in testing?
  • Are specific user segments having worse experiences?
  • Are there signs of model drift or data drift?

A/B Testing AI Features

AI A/B Testing is Different

Traditional A/B testing assumes consistent behavior. AI is stochastic - the same input can give different outputs. This means:

  • Higher variance: Need more samples for significance
  • Harder to measure: Quality is subjective, not a click rate
  • Risk of harm: Bad AI output can hurt users, not just convert poorly

A/B Test Sample Size Calculator

Small Effect Size (5% lift)

To detect with 95% confidence:

~3,000 samples per variant

At 1000/day: ~1 week

Medium Effect Size (10% lift)

To detect with 95% confidence:

~800 samples per variant

At 1000/day: ~2 days

Large Effect Size (20% lift)

To detect with 95% confidence:

~200 samples per variant

At 1000/day: ~hours

User Feedback Integration

Explicit Feedback

  • Thumbs up/down
  • Star ratings
  • Free-text comments
  • Error reports

Pro: Clear signal

Con: Low response rate (~2%)

Implicit Feedback

  • Did user continue the task?
  • Did they regenerate?
  • Did they edit heavily?
  • Time to next action

Pro: High volume

Con: Noisy, needs interpretation

PM Insight

The 10x rule: For every hour spent building an AI feature, plan to spend 10 hours monitoring and improving it. AI isn't "set and forget" - it's "launch and learn."

How to Explain Feedback Loops to Stakeholders

"Think of AI like a new employee who needs ongoing coaching. We monitor their performance, collect feedback from users, and continuously improve based on what we learn. We have dashboards that alert us if quality drops, and we run A/B tests before rolling out changes. This ensures the AI keeps getting better, not worse, over time."

Section 6 Summary

Key Takeaways

  1. Different AI types need different metrics: ML metrics, LLM dimensions, RAG faithfulness, Agent task completion
  2. LLM-as-judge scales evaluation: Use it to filter, not as final judgment - ~85% agreement with humans
  3. Human evaluation is the gold standard: But measure inter-rater reliability (Kappa > 0.4)
  4. Feedback loops never stop: Monitor, evaluate, improve - plan 10x the effort for post-launch vs build
