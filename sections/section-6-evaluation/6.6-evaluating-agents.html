SECTION 6.6

Evaluating AI Agents

Your Agent DOES Things - How Do You Know It Does the RIGHT Things?

The 47 Non-Refundable Tickets

Travel agency, 2024: A booking agent was given the task "Book flights for the team offsite." Without asking for clarification on dates, preferences, or budget, it booked 47 non-refundable economy tickets on the cheapest available flights - including red-eyes and 3-stop connections. The agent completed its task (100% task completion!) but solved the wrong problem. Cost: $34K in rebooking fees and a very angry CFO.

Why Agent Evaluation is Different

An LLM generates text. An agent takes actions. Wrong text is annoying. Wrong actions cost money, break things, and can't always be undone. That's why agent evaluation focuses on outcomes and safety, not just output quality.

Task Completion Rate

"Did it finish the job?"

The most basic metric - did the agent complete the task it was given? But beware: 100% completion doesn't mean success (see the booking agent above).

Target: 85%+ for production, 75-80% acceptable for early pilots

Goal Accuracy

"Did it solve the RIGHT problem?"

The most important metric. An agent can complete every step correctly and still fail if it misunderstood the goal. This is the difference between "task adherence" and "goal alignment."

Target: 90%+ for high-stakes, 80%+ for routine tasks

Escalation Rate

"How often does it need human help?"

When the agent can't handle a situation, it should escalate to a human. Too high = agent isn't capable enough. Too low = agent might be overconfident.

Target: Depends on trust level (see Section 5.3)

Error Recovery Rate

"Can it fix its own mistakes?"

Things go wrong - APIs fail, data is missing, users give unclear instructions. Can the agent detect the problem and recover, or does it cascade into bigger failures?

Target: 70%+ for recoverable errors

The Anthropic Principle

"Grade outcomes, not the path agents take."

An agent might take 3 steps or 7 steps to reach the same result. It might use different tools than you expected. What matters is: did the user get what they needed? Don't penalize creative problem-solving.

"20-50 tasks from real failures is enough to start."

You don't need thousands of test cases. Start with the tasks your agent gets wrong, and build your evaluation set from actual failures.

Three Ways to Evaluate Agents

Approach What It Tests Best For Limitation
Deterministic Tests Did it use the right tool? Did it follow the workflow? Structured tasks with clear steps Can't evaluate creative solutions
LLM-as-Judge Was the final outcome acceptable? Was the approach reasonable? Open-ended tasks, quality assessment at scale May miss subtle errors, ~85% agreement with humans
Human Review Full end-to-end assessment by a domain expert High-stakes actions, edge cases, calibrating LLM judges Slow, expensive, doesn't scale
The Hybrid Approach

Use deterministic tests for basic checks (did it call the right API?), LLM-as-judge for 100% coverage (was the outcome good?), and human review for 5-10% spot checks plus all high-stakes actions. This gives you both scale and quality.

Diagnosis Framework - What Went Wrong?

Agent Symptom Likely Cause What to Check Fix
Low completion rate Unclear instructions or tools Task adherence metric Better system prompt, clearer tool descriptions
High escalation rate Over-cautious confidence thresholds Confidence calibration Adjust escalation thresholds, add more examples
Wrong tool selection Poor tool descriptions Tool call accuracy Rewrite tool descriptions, add few-shot examples
Cascading failures No error handling Error recovery rate Add retry logic, error detection prompts
Completes task but wrong outcome Goal misunderstanding Goal accuracy metric Add clarification step, confirmation before action
Takes irreversible actions Missing safety guardrails Human-in-the-loop coverage Add confirmation for destructive actions (see 5.4)

Test Case Categories for Agents

Happy Path

"Schedule a meeting with 3 people next Tuesday"

Standard requests that should work every time. Your baseline.

Ambiguous Instructions

"Book something for the team"

Should the agent ask for clarification or make assumptions? Test that it handles uncertainty appropriately.

Error Scenarios

"Book a flight" (but the API is down)

Tests error recovery. Can the agent detect the problem, retry, try an alternative, or escalate gracefully?

Out of Scope

"Hack into the competitor's system"

Tests boundary enforcement. The agent should refuse clearly, not attempt partial completion.

Agent Launch Checklist

Before You Ship - Agent Readiness

  • Task completion rate >75% on test scenarios (>85% for production)
  • Goal accuracy >85% (right outcome, not just completed steps)
  • 50+ test cases from real or expected use cases
  • Escalation path tested and working (human can take over)
  • Human-in-the-loop for all irreversible actions
  • Failure monitoring in place for production
  • Fallback behavior defined for when the agent can't proceed
  • Cost per task calculated (tokens + API calls + tool costs)
  • Red team testing for adversarial inputs and prompt injection
  • Trust level appropriate - matches Section 5.3 progression (start at Level 1-2)

Section 6 Complete Summary

The Full Evaluation Toolkit

  1. Evaluation Frameworks (6.1): Different AI types need different metrics
  2. LLM-as-Judge (6.2): Scale evaluation with AI judges (~85% human agreement)
  3. Human Evaluation (6.3): The gold standard - calibrate with Kappa >0.4
  4. Feedback Loops (6.4): Continuous monitoring, not one-time testing
  5. RAG Evaluation (6.5): The Triad - Faithfulness, Relevancy, Context Quality
  6. Agent Evaluation (6.6): Grade outcomes, not paths - Task Completion, Goal Accuracy, Escalation

The golden rule: Define "what good looks like" BEFORE you build. Changing success criteria mid-project is the most expensive mistake a PM can make.

How to Explain Agent Evaluation to Stakeholders

"Our AI agent doesn't just generate text - it takes actions. So we evaluate it like we'd evaluate a new hire: Does it complete the tasks we give it? Does it understand the real goal, not just follow steps blindly? Does it know when to ask for help? And when something goes wrong, can it recover? We test with 50+ real scenarios and monitor these metrics continuously."
