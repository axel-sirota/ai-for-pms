SECTION 6.5

Evaluating RAG Systems

Your RAG Works - But Does It Work WELL?

The Hallucinating Legal Bot

A legal tech startup, 2024: A RAG-powered legal chatbot was answering attorney questions using their firm's document library. It looked great in demos. Then a junior associate cited one of its answers in a court filing - a regulation that didn't exist. The chatbot had hallucinated a plausible-sounding legal citation that wasn't in any retrieved document. Cost: $50K+ in legal fees and a formal court sanction.

Why RAG Needs Special Evaluation

A standard LLM can be wrong because it doesn't know the answer. A RAG system can be wrong in a more dangerous way - it has the right documents but generates the wrong answer. Users trust RAG more (because it has "sources"), which makes hallucination even more costly.

The RAG Triad - Three Things That Can Go Wrong

Think of RAG evaluation like checking a research assistant's work. Three things can fail independently:

1. Faithfulness

"Is the AI making stuff up?"

Every claim in the answer should be supported by the retrieved documents. If the AI adds information that isn't in the source material, that's hallucination.

How to measure: Count claims in the answer. Check each against the retrieved context. Supported claims / Total claims = Faithfulness score.

Target: >90% for production

2. Answer Relevancy

"Did it answer MY question?"

The answer might be accurate but not relevant. If you ask "What's our refund policy?" and get a technically correct essay about your company history, that's an answer relevancy failure.

How to measure: Does the answer directly address the question asked - not a similar question, not a related topic?

Target: >85% for production

3. Context Precision

"Did we find the right documents?"

The retrieval step matters as much as the generation step. If the system retrieves irrelevant documents, even the best LLM can't give a good answer.

How to measure: Of the top-5 retrieved documents, how many are actually relevant to the question?

Target: >70% at top-5

PM Decision Point

When your RAG system fails, the fix depends on WHERE it failed:

Diagnosis Framework - What Went Wrong?

Symptom Likely Cause Metric to Check Fix
Wrong answers despite good docs Hallucination Faithfulness Tighter prompts, lower temperature
Correct but off-topic answers Poor relevance matching Answer Relevancy Better prompt engineering
Wrong documents retrieved Bad retrieval Context Precision Improve chunking, better embeddings
"I don't know" too often Missing context Context Recall Add more docs, adjust retrieval threshold
Answers mix multiple topics Chunk too large or too small Context Precision Re-chunk documents (see Section 4.3)
Made-up citations/sources Hallucinated references Faithfulness Citation verification step, strict grounding

Building Your RAG Test Set

Start Small, Start From Failures

Anthropic's guidance: "20-50 tasks from real failures is enough to start." Don't try to build a comprehensive test set on day one. Start with the questions your RAG system gets wrong, and build from there.

Test Case Categories for RAG

Simple Fact Lookup

"What is our return policy window?"

Tests basic retrieval and faithfulness. The answer should come directly from one document.

Multi-Document Synthesis

"How do our pricing tiers compare?"

Tests whether the system can combine information from multiple sources without hallucinating connections.

No Good Answer Exists

"What's our policy on cryptocurrency payments?"

Tests whether the system says "I don't know" instead of making something up. This is often the most important test.

Ambiguous Questions

"Tell me about the update"

Tests whether the system asks for clarification or makes assumptions. Both can be valid - you decide which behavior you want.

RAG Launch Checklist

Before You Ship - RAG Readiness

  • Faithfulness score >90% on your test set
  • Context precision >70% at top-5 retrieved documents
  • 50+ test cases covering happy path, edge cases, and "no answer" scenarios
  • Human review of 20% of test outputs (don't trust automated scores alone)
  • Fallback behavior defined for when the system can't find a good answer
  • Hallucination monitoring in place for production
  • Cost per query calculated (retrieval + generation costs)
  • Latency P95 acceptable (retrieval adds latency)
  • Citation display working so users can verify sources
  • Red team testing for prompt injection through documents

Connecting the Dots

How to Explain RAG Evaluation to Stakeholders

"How do we know our knowledge base AI isn't making things up? We measure three things: Did it find the right documents? Is the answer actually supported by those documents? And does it answer the question that was asked? We test with 50+ real questions, and we monitor these scores continuously in production. If faithfulness drops below 90%, we get an alert."
