SECTION 5.4

Human-in-the-Loop Design

Designing Safe Agent Systems with Appropriate Checkpoints

The Missing Checkpoint

Knight Capital's Fatal Flaw: Their trading system had no human checkpoint for unusual activity. When the algorithm started executing erroneous trades at 100x normal volume, there was no automatic stop. By the time humans noticed, $440 million was gone.

The Checkpoint Decision Framework

flowchart TD
    A[Agent Action] --> B{Is it reversible?}
    B -->|Yes| C{Cost if wrong < $100?}
    B -->|No| D[REQUIRE APPROVAL]
    C -->|Yes| E[Allow + Log]
    C -->|No| F{Confidence > 95%?}
    F -->|Yes| G[Allow + Notify]
    F -->|No| D

Types of Human Checkpoints

Checkpoint Type Description Use When Example
Pre-Action Human approves before AI acts Irreversible, high-value actions "Approve this $5,000 purchase?"
Post-Action AI acts, human can undo Reversible, medium-value actions "Meeting scheduled. Undo?"
Sampling Human reviews random % of actions High-volume, low-risk actions Review 5% of auto-responses
Threshold Auto-approve below threshold Value-based decisions Auto-approve if < $500
Confidence Approve if AI is confident Uncertain situations If confidence < 80%, ask human
Exception Human handles edge cases Unusual patterns detected Escalate if customer is angry
PM Decision Point

For each agent action, decide:

  • Checkpoint type: Pre, post, sampling, threshold, confidence, or exception?
  • Threshold values: What $ amount? What confidence %?
  • Sampling rate: Review what % of actions?
  • Escalation path: Who handles exceptions?

The Friction vs Safety Tradeoff

More Checkpoints

  • Safer (catch more errors)
  • Slower (users wait)
  • More expensive (human time)
  • Better for: High-risk, regulated, new systems

Fewer Checkpoints

  • Faster (instant action)
  • Riskier (errors slip through)
  • Cheaper (less human involvement)
  • Better for: Low-risk, proven systems
2-5% Typical sampling rate for proven systems
$500 Common auto-approval threshold
80% Typical confidence threshold

UX Patterns for Transparency

Pattern Description Example
Show the reasoning Explain what the AI is doing "Searching for flights... Found 3 options"
Confirm before acting Ask before irreversible actions "Ready to book. Confirm purchase?"
Show confidence Indicate how sure the AI is "90% confident this is correct"
Easy undo Clear path to reverse "Meeting scheduled. [Undo]"
Summarize actions Recap what was done "Booked flight, sent confirmation email"

Anti-Patterns to Avoid

Don't Do This
  • Black box: "Done!" (What did it do?)
  • No undo: Irreversible action with no way back
  • Overconfidence: "I have booked your flight" vs "I'm ready to book"
  • Hidden actions: Agent does things user didn't ask for
  • Alert fatigue: Too many checkpoints - users start auto-approving

PM Insight

Design for the 1% case. 99% of the time your agent works perfectly. But the 1% failure case is what makes headlines. Build your checkpoints around the worst-case scenario, then optimize for speed once you've proven safety.

How to Explain Human-in-the-Loop to Stakeholders

"Every agent action goes through a decision tree. Small, reversible actions happen automatically. Big or irreversible actions require human approval. We can tune the thresholds - tighter for safety, looser for speed. Right now we're starting conservative and will loosen as the system proves itself."

Section 5 Summary

Key Takeaways

  1. Copilot vs Agent: Start as copilot (suggests), graduate to agent (acts) based on track record
  2. ReAct Pattern: Agents reason → act → observe in cycles. You control the tools and limits.
  3. Trust Progression: Level 0 → Level 3 takes months, not days. Demotion can happen instantly.
  4. Human-in-the-Loop: Every checkpoint is a tradeoff between safety and speed. Design for the worst case.
