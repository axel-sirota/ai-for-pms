SECTION 5.2

The ReAct Pattern

How Agents Reason, Act, and Observe

The Core Loop

ReAct = Reason + Act
Agents don't just respond - they think, take action, observe results, and repeat. This loop is what makes them powerful and what makes them risky.

The ReAct Cycle

    R[REASON

    A --> O[OBSERVE

Example: Travel Booking Agent

User Request: "Book me a flight from NYC to LA next Friday under $500"

Step Phase What Happens
1 REASON "I need to search for flights from NYC to LA on Friday with max price $500"
2 ACT search_flights(from="NYC", to="LA", date="Friday", max_price=500)
3 OBSERVE Found 3 flights: Delta $450, United $380, JetBlue $420
4 REASON "United is cheapest at $380. I should present options to the user."
5 ACT present_options([Delta $450, United $380, JetBlue $420])
6 OBSERVE User selected United $380
7 REASON "User confirmed United. I should book the flight."
8 ACT book_flight(flight="United", price=380)
9 OBSERVE Booking confirmed. Confirmation #UA12345
PM Decision Point

Notice step 5 - the agent presented options instead of auto-booking. This is a human checkpoint. As PM, you decide:

  • Which actions need human confirmation?
  • What thresholds trigger checkpoints? ($500? $1000?)
  • How many ReAct cycles before forcing a stop?

Where ReAct Goes Wrong

Infinite Loops

Agent keeps searching, never finds a good answer, loops forever.

Fix: Max iterations limit (e.g., 10 cycles)

Wrong Tool Selection

Agent reasons incorrectly and picks the wrong action.

Fix: Better tool descriptions, validation

Hallucinated Tools

Agent tries to use a tool that doesn't exist.

Fix: Strict tool validation before execution

Cascading Errors

One bad observation leads to worse reasoning in the next cycle.

Fix: Error detection and recovery paths

Why PMs Care About ReAct

You don't need to implement ReAct - that's engineering's job. But you need to understand it because:

  • You define the tools: What can the agent do?
  • You set the limits: How many cycles? What thresholds?
  • You design the checkpoints: When does it stop and ask?
  • You debug the failures: Understanding the loop helps diagnose problems

How to Explain ReAct to Stakeholders

"The agent works in cycles: it thinks about what to do, takes an action, sees the result, and repeats until done. Like a smart employee who checks their work as they go. We control how many cycles it can run and which actions need approval."
