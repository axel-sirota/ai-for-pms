2.2 The ML Lifecycle

What the timeline really looks like - and your role at each phase

The #1 Thing PMs Get Wrong

Most PMs think ML projects are mostly about building models. In reality, 60% of the time is data work - collecting, cleaning, labeling, and validating data. If your timeline doesn't account for this, your project will be late.

Your Role at Each Phase

Phase Duration What's Happening PM Responsibilities
Data Collection & Cleaning 2–4 months Team is acquiring, cleaning, and labeling training data
  • Define what "good data" means
  • Approve data sources (privacy, bias, freshness)
  • Unblock access to data systems
  • Set labeling guidelines
Model Development 1–2 months Data scientists are training and tuning models
  • Define success metrics (precision? recall? both?)
  • Identify test edge cases from domain knowledge
  • Review early results for "does this make sense?"
Evaluation 2–4 weeks Testing on held-out data, stress testing
  • Accept or reject based on business metrics
  • Test with real users (shadow mode)
  • Define "good enough" threshold
Deployment 2–4 weeks Integrating model into production system
  • Define monitoring alerts and dashboards
  • Plan rollout strategy (canary, A/B, full)
  • Prepare rollback plan
Monitoring Ongoing Tracking performance, detecting drift
  • Review performance dashboards weekly
  • Trigger retraining when metrics drop
  • Plan for model versioning

Questions to Ask at Each Phase

Before Starting

  • "Do we have the data this requires?"
  • "What does success look like in business terms?"
  • "What's the cost of getting it wrong?"
  • "Is the timeline realistic given data work?"

During Development

  • "What's the current accuracy on test data?"
  • "Have we tested the edge cases I identified?"
  • "Where does the model fail most?"
  • "Are there biases in the training data?"

Before Launch

  • "What happens when the model is wrong?"
  • "How will we know if performance degrades?"
  • "What's the rollback plan?"
  • "Who's on call for the first week?"

Common Timeline Mistakes

MistakeRealityWhat to Do
"We'll have a model in 2 weeks" You might have a prototype. Production takes months. Separate POC timeline from production timeline
"The data is ready" Data is never ready. Cleaning takes 2-4 months. Budget 60% of timeline for data work
"We'll launch and iterate" ML models don't iterate like features. Retraining is expensive. Define "good enough" before building, not after
"The model is done" Models degrade. Maintenance is forever. Budget ongoing monitoring and retraining costs

Stakeholder Framing

When your VP asks "Why does this ML project take so long?":

"60% of ML project time is data work - collecting, cleaning, and validating training data. The actual model training is only about 20% of the effort. We can show a demo in weeks, but a production-quality system that handles edge cases reliably takes 6-9 months. Rushing past data quality is the #1 reason ML projects fail."
