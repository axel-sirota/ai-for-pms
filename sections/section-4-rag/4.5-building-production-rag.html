Section 4 - RAG

Production RAG

Architecture patterns, cost considerations, and the questions to ask before shipping.

Failure Story: The $50K/Month Surprise

A startup launched their RAG-powered customer support bot. In testing, costs were $500/month. After launch, a viral TikTok drove 100x traffic.

Their bill hit $50,000 in one month. No rate limiting, no caching, no cost alerts.

They had to take the bot offline for 2 weeks while implementing safeguards.

Lesson: Production RAG needs cost controls from day one, not after the viral moment.

PM Pre-Launch Checklist

Before shipping RAG to production, verify:

  • Cost alerts at 50%, 80%, 100% of budget
  • Rate limiting per user/session
  • Caching for common queries
  • Fallback when retrieval confidence is low
  • Monitoring for all 5 failure modes
  • Human escalation path

Cost Components

Component Cost Driver Optimization
Embedding (docs) One-time: ~$0.02/1M tokens Only re-embed changed docs
Embedding (queries) Per query: ~$0.02/1M tokens Cache common queries
Vector storage ~$0.25/GB/month Prune old/unused docs
Vector queries ~$0.0001/query Batch similar queries
LLM generation $0.15-$15/1M tokens Smaller models, shorter prompts, caching
The 80/20 Rule of RAG Costs

LLM generation is 80%+ of your cost. The vector database is cheap.

Optimization priority: (1) Cache responses, (2) Use smaller models for simple queries, (3) Reduce retrieved chunks, (4) Shorten prompts.

Questions to Ask Engineering

Before Build

  • What chunking strategy for our doc types?
  • How do we handle questions not in our docs?
  • What's the latency target? (affects model choice)
  • How will we update docs without downtime?

Before Launch

  • What's our cost per query at expected volume?
  • Do we have rate limiting and cost alerts?
  • What's the human escalation path?
  • How do we monitor for the 5 failure modes?

Post-Launch

  • What % of queries hit cache vs. new generation?
  • What's our retrieval success rate?
  • Which failure mode is most common?
  • What queries are users asking that we don't cover?

Monitoring Dashboard

A production RAG system needs these metrics visible:

Metric What It Tells You Alert Threshold
Retrieval confidence Are we finding relevant chunks? <0.7 avg = investigate chunking
Response latency User experience >5s p95 = optimize
Cost per query Budget tracking >$0.10 = review model/caching
Cache hit rate Efficiency of caching <30% = expand cache strategy
Human escalation rate System confidence >20% = investigate failures
User satisfaction Answer quality <70% helpful = debug pipeline
